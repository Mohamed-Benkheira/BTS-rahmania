Key Technical Feat: Partial Index

Rule: A project can have only ONE active assignment at a time, but retains full history:

CREATE UNIQUE INDEX single_active_assignment ON assignments (project_id) WHERE status IN ('approved', 'active');
Why this matters: Data safety is enforced by the database engine. Even if two managers click approve at the same second, PostgreSQL rejects the second one.

Key Feature: The Recommendation Engine

An intelligent matching formula to find the right candidate for every project

09 / 16
Match Score = 40% Skills + 20% Certs + 15% Languages + 15% Availability + 10% Workload
What the Engine Evaluates
Skills (40%): Matches proficiency level (1 to 5) to project requirements.
Certifications (20%): Must be verified and non-expired.
Availability (15%): Calendar dates match project timeline.
Workload (10%): Prioritizes staff who have free capacity.
Smart Safeguards
Mandatory Blockers: If a project requires a strict certificate, candidates without it are excluded.
Overload Protection: Employees already at 100% capacity are filtered out.
1-Click Assignment: Manager can directly assign the top-ranked candidate.

Technical Challenges & How We Solved Them

Four concrete engineering obstacles overcome during development

13 / 16
1. Single Active Staff vs. History
Problem: Standard database UNIQUE rules would wipe out past assignment history.
Solution: PostgreSQL Partial Unique Index filtered only on 'approved' and 'active' status.
2. React with Laravel without 2 APIs
Problem: Writing a separate REST API meant duplicating validation rules and routing models.
Solution: Used Inertia.js protocol to pass controller data straight into React components.
3. Candidate Scoring Speed
Problem: Scoring 300+ profiles caused slow database queries on skills and certificates.
Solution: Pre-filtered inactive staff in SQL and used eager-loading to load data in one query.
4. Circular Manager Relationships
Problem: Departments point to managers, and employees point to departments.
Solution: Created tables first, then attached manager foreign keys in a second migration.
